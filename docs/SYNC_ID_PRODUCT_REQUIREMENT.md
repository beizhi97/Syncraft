# 同步 ID 产品需求记录

状态：已确认需求，尚未实现，不属于当前 Protocol v1 运行时合同。

实施与安全计划：`docs/SYNC_ID_SECURITY_IMPLEMENTATION_PLAN.md`。

记录日期：2026-07-13。

## 1. 产品目标

用户不需要理解 MinIO bucket、对象前缀、设备空间、共享空间或远端目录。
多台设备只要加入同一个“同步 ID”，就应自动同步同一份服务端内容。

用户可感知的核心关系是：

```text
一个同步 ID = 一份同步内容
多台设备 + 同一个同步 ID = 多台设备共享并同步这份内容
```

“内容一致”指各设备成功完成同步后，逻辑文件集合和文件内容一致；不承诺所有设备在传输过程中实时逐字节一致。

## 2. 术语

- **同步 ID**：用户用于选择或加入同一份同步内容的稳定标识。建议内部字段名为 `syncSpaceId`，避免与设备 ID、用户 ID 混淆。
- **同步空间**：同步 ID 对应的服务端逻辑数据集合。
- **设备身份**：每台客户端自己的身份和凭据。设备身份与同步 ID 分离，同一同步空间可以包含多台不同设备。
- **成员权限**：设备在同步空间中的读取、写入、删除和管理权限。

## 3. 目标交互

普通用户创建同步任务时只需要：

1. 选择本地文件夹。
2. 创建或输入同步 ID，也可以通过服务端签发的加入凭据加入。
3. 选择同步方式或采用服务端下发的默认策略。
4. 启动同步。

正常流程不再要求用户填写或理解：

- MinIO bucket；
- `devices/{clientName}`、`shared/{folder}` 等对象前缀；
- “设备空间/共享空间”选项；
- 原始远端目录或 S3 路径；
- MinIO/S3 endpoint、N1 专用主机名或客户端/服务端内部路由。

管理端可以展示同步空间名称、成员、容量和状态，但底层 bucket/prefix 只作为运维信息，不作为普通用户配置项。

## 4. 服务端映射

服务端负责把同步 ID 唯一映射到实际对象存储目标：

```text
syncSpaceId -> bucket + managed prefix + policy
```

三台设备加入同一个同步 ID 时，服务端必须给三台设备下发同一个逻辑存储目标，同时保留各自独立的设备身份、心跳、审计记录和可撤销凭据。

用户输入相同同步 ID 不能依赖客户端自行拼接路径。最终映射、权限校验和成员关系必须由服务端确认，防止路径碰撞、越权访问和手工输入错误。

同步 ID 对应的是逻辑内容和成员关系，不得绑定 `n1-minio.sfsc` 之类的单机部署名称。客户端需要的存储传输路径应由运行时通过版本化、可迁移的内部服务描述建立；普通用户只看到 `sync.970506.xyz`、同步 ID 和连接状态。

## 5. 安全与一致性约束

同步 ID 只负责标识内容，不能作为访问凭据。每台设备必须使用独立 SyncKey 加入，并由服务端建立可撤销的同步空间成员关系和最小权限存储授权；仅输入或猜中同步 ID 不得读取、写入、枚举或确认空间存在。

开放多设备写入前必须完成以下能力：

- 同一同步空间的任务互斥或并发协调；
- 同名文件并发修改的冲突检测和冲突副本策略；
- 删除传播规则、危险删除确认和恢复能力；
- 断网重连、重复请求和重试幂等；
- 同步完成后的文件清单、大小和内容完整性验证；
- 成员加入、移除、凭据轮换和权限撤销；
- 按同步 ID 隔离日志、状态、配额和审计信息。

在上述能力完成前，试用阶段的安全默认模式应为单写入端、多读取端；不得把多台设备同时双向写入宣传为稳定能力。

## 6. 与当前模型的关系

当前版本仍使用以下底层模型：

```text
设备私有空间: {bucket}/devices/{clientName}/{remoteFolder}
共享空间:     {bucket}/shared/{remoteFolder}
```

后续重设计时可保留 bucket/prefix 作为内部实现和兼容层，但应从普通客户端主流程中移除“空间”和“远端目录”配置。旧任务迁移时，现有共享路径可以转换为同步空间记录，并由服务端分配同步 ID；设备私有路径可转换为只有一个初始成员的同步空间。

本记录不修改当前 Protocol v1 字段、SyncKey 行为或运行时路径规则。涉及协议字段和签发流程的变化，应进入单独设计评审，并根据兼容性决定作为 Protocol v1 扩展或未来 Protocol v2 变更。

## 7. 验收标准

- 三台使用不同设备身份的客户端加入同一个同步 ID 后，服务端显示其属于同一同步空间。
- 三台设备必须使用各自的 SyncKey/设备凭据；复制同步 ID 或复制其他设备 profile 均不能替代授权。
- 任意设备不需要知道或输入 bucket、prefix、设备空间、共享空间或远端目录。
- 未经授权的设备即使猜中有效同步 ID，也不能确认空间存在或访问任何对象。
- 单写入端上传完成后，其他设备可以拉取并通过完整性校验得到相同内容。
- 未加入该同步 ID 的设备不能读取、写入或枚举该同步空间。
- 设备被移除或凭据撤销后，不能继续访问该同步空间。
- 多端写入启用前，冲突、删除、断网恢复和幂等测试全部通过。
