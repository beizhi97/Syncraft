# SFSC 当前 UI/UX 问题清单

## 结论

现有实现已经具备完整的状态合同、安全确认、错误恢复和诊断能力，主要问题不是“缺功能”，而是信息层级仍按开发模块排列，普通用户需要同时理解组件、隧道、心跳、Profile、仓库和同步进程，才知道下一步做什么。重设计应保留全部接口与 DOM 合同，把复杂度重新分层。

## 客户端

1. 顶部同时出现组件、Profile、隧道、心跳、同步五个徽标，状态密度高但缺少主次。普通用户真正关心的是“能否同步、正在做什么、下一步是什么”。
2. 首次使用信息与日常工作台共用页面，空状态包含安装说明、T-key 导入和安全提示，主任务入口不够集中。
3. 同步任务表单一次暴露方向、空间、远端目录、调度、并行文件、线程、镜像、双向基准和限速，基础任务与专家参数混杂。
4. “保存任务”“开始同步”“停止同步”并列，未形成随状态变化的单一主操作。停止操作在空闲时仍占据视觉位置。
5. 进度面板空间较大，但空闲时信息价值低；同步中又缺少阶段、剩余工作和停止反馈的清晰层级。
6. 设置抽屉承载 T-key、组件、协议、本地状态、隧道、命令预览、历史和日志，滚动距离长，诊断信息与常用设置混合。
7. 历史位于设置抽屉深处，但它是用户判断“是否同步成功”的日常信息，应提升为一级入口。
8. 错误处理逻辑已经很细，但错误码、原因、可重试性和恢复动作未在布局上形成固定模板。
9. 长路径、当前文件和远端目标容易挤压布局；需要统一省略、复制和悬浮查看策略。
10. 窗口关闭后进入托盘是关键行为，现有主界面没有稳定、低干扰的说明位置。

## 服务端控制台

1. VLESS、存储、T-key、设备四个页签是技术模块划分，缺少“服务是否可签发、设备是否可同步”的运营视角。
2. 状态条与统计条占据较多首屏高度，却没有把异常按影响范围排序。
3. VLESS 配置字段密集，REALITY 密钥和应用配置等高风险操作与一般字段距离过近。
4. 存储配置与仓库生命周期管理混在一屏，管理员难以区分“连接参数”和“业务仓库”。
5. T-key 生成、复制、测试兑换集中在同一区域，但一次性凭据的生命周期、是否已使用和安全提示不够显著。
6. 设备列表需要同时表达在线、启用、同步、兼容性、冲突和最近心跳；卡片式表达会浪费横向空间，适合改为密集表格。
7. 危险操作已有页面级确认合同，但入口仍应收进每行菜单或高级区域，避免与日常动作并列。
8. 私钥、Secret Key、完整 VLESS URI 必须默认遮蔽，并按需短暂显示；复制动作也应明确已复制内容类型。

## 跨端一致性

- 同一状态在两端应使用同一色义和词汇：正常、同步中、警告、失败、离线、协议不兼容。
- 客户端强调“任务和下一步”，服务端强调“密度、影响范围和可诊断性”。
- 不改变 API 路径、枚举、错误码含义、T-key 流程或关键 DOM id。
- 不在任何原型中出现真实 Token、T-key、私钥、设备名、仓库名或本机路径。
